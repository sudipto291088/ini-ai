1️⃣ Structured JSON enforcement

I had to make the model return strictly structured JSON for question generation.

The challenge:

Models sometimes return reasoning-only output.

Sometimes they hit max_output_tokens.

Sometimes they produce incomplete responses.

I solved it by:

Using the Responses API properly.

Enforcing JSON mode.

Implementing robust extraction logic.

Routing different models for different tasks.

Debugging reasoning-token failures.

Handling incomplete responses gracefully.

That shows:
System-level debugging capability.

2️⃣ Model routing strategy

I separated:

Fast model for question generation (JSON stability)

Deep model for research-level answers

That reduced failure rate and improved latency.

That shows:
Architectural thinking, not just API usage.

3️⃣ Separation of concerns

I separated:

Interrogate (questions-only)

Answer (on-demand generation)

Streamlit rendering

Caching layer

Backend API

That prevents re-computation and improves performance.

That shows:
Backend + frontend orchestration.

4️⃣ Performance tradeoffs

I learned that:

Large models can burn reasoning tokens.

JSON mode can fail silently.

Latency is real.

Caching is essential.

Instead of forcing intelligence,
I optimized structure.

That shows:
Pragmatic engineering judgment.

5️⃣ Real-world debugging

You handled:

401 API errors

429 quota errors

Unsupported parameters

JSON parsing failures

Encoding issues (UTF-8)

Incomplete reasoning outputs

Model-specific constraints

That shows:
You didn’t just build.
You stabilized.
